## Method

Each scenario replaces the example's schema with a full schema file, runs the example's own `emit` script, and restores the example with `git checkout -- <example>/src`. The command was always:

```bash
cd examples/<example> && mise exec -- pnpm emit
```

`pnpm emit` runs `prisma contract emit`. The CLI writes a JSON envelope because its output is not a terminal. The scenario schemas, the runner script and the raw output of every run are in `wip/qa/` (`scenarios/`, `run.sh`, `out/`). After every scenario `git status` was clean.

A baseline emit of each example, with no schema change, wrote no diff.

The language server was checked by starting `prisma lsp --stdio` in `examples/mongo-demo` with a small client (`wip/qa/lsp-client.mjs`). It opens the scenario text without writing it to disk and prints the published diagnostics. LSP positions are zero-based; CLI positions are one-based.

## Observations

These do not fail the spec. They are recorded for the reader.

- A member refusal points at the whole member, such as `Unknown = "NaN"`, not only at the value. The spec says "at the member", so this is correct.
- The vector message counts elements from 1 ("element 1 is NaN" for `[NaN]`). The unit tests expect the same.
- The envelope's `why` differs by cause: an interpretation refusal says `PSL to Mongo contract interpretation failed`, and an unresolved field says `Schema has 1 error`. This is not part of slice 1.
