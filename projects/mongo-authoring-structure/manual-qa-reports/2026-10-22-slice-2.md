## Failures

### 1. `prisma contract emit` drops the preset warning when the schema is refused

**Reproduction:** in `examples/mongo-demo/src/contract.prisma`, change `kind String` to `kind String?` and add `stamp temporal.timestamp()` to `Post`. Then run `pnpm emit`. You can also use `wip/qa/scenarios/p8-preset-no-effect-with-error.prisma`.

**What happens:** the CLI prints only the discriminator error, in the human output and in `--json`. The language server shows the warning and the error together, and so does TypeScript (R6).

**Why it matters:** the slice's upgrade note (`mongo-newly-accepted`) and the error reference entry for `PSL_PRESET_WITHOUT_EFFECT` both say the warning "is now reported even when the schema is refused". The CLI does not show it.

**Cause:** in `packages/1-framework/3-tooling/cli/src/control-api/operations/contract-emit.ts`, `sourceWarnings` is collected, but when `loadContractSourceWithStack` fails, the code throws without the warnings. The branch does not change this file, so the CLI behaved this way before the slice. Either the CLI should print the warnings with the failure, or the docs should say "in the language server" for the refused case.

### 2. `mongoContract` without `target` gives a JavaScript `TypeError`, not a clear message

**Reproduction:** use `wip/qa/qa-notarget-copy/prisma.config.none.ts` and `prisma.config.output.ts`, placed in a folder under `cli-integration-test-app`.

**What happens:** the user sees `Cannot read properties of undefined (reading 'output')` (C1) or `Cannot read properties of undefined (reading 'defaultNamespaceId')` (C2). Neither message names `target` or the target pack, and C2's next step talks about `contract.source.load`, which a user never writes.

**Mitigation:** `MongoContractOptions.target` is required in the type, so a TypeScript config fails its type check first. The `CONFIG.EVALUATION_FAILED` and `CONTRACT.SOURCE_LOAD_FAILED` messages above are what a JavaScript config sees, and what a TypeScript config sees when nothing checks its types. `prisma contract emit` does not type-check the config.

**Suggested fix:** `mongoContract` checks `options?.target` and throws an error that says to pass `{ target: mongoTargetPack }` from `@prisma/orm-mongo/target/pack`, as the upgrade note does.

## Other observations

- An app that depends only on `@prisma/orm-mongo` cannot import `mongoContract`. It is exported from `@prisma/orm-family-mongo/contract-psl/provider`. The app upgrade note shows the pack import from `@prisma/orm-mongo/target/pack` but does not say where an app imports `mongoContract` from.
- For a duplicate index, PSL reports `PSL_INVALID_INDEX` and TypeScript reports `CONTRACT.NAME_DUPLICATE`. The spec keeps TypeScript's existing codes, so this is expected.
- PSL index refusals (P2, P3) keep their older wording, such as "include/exclude options are only valid when ...". The TypeScript wording for the same rules is newer and names the index.
- An untracked file, `test/integration/test/authoring/zz-review-probe.test.ts`, appeared during the run. QA did not create it; it probably belongs to a reviewer agent. I left it in place.
