## 11. TypeScript

```ts
export const contract = defineContract({}, ({ field, model, type }) => {
  const UpdatedAt = field.column(type.TimestampString(3)).onCreate(gen.now()).onUpdate(gen.now());
  const Post = model('Post', {
    fields: {
      id: field.column(type.String()).id().onCreate(gen.uuid()),

  return { models: { Post } };
});
```

## Findings

All are low severity. None breaks an acceptance criterion.

1. Low. `B = A` and `X = temporal.UpdatedAt` say only `references unsupported base type "A"`. They do not say that an alias may not name another alias, or what to write instead (the base's type constructor and attributes). The message is unchanged from `main` for `B = A`, which spec D3 keeps.
2. Low. `temporal.CreatedAt(3)` is reported under `PSL_INVALID_ATTRIBUTE_ARGUMENT`, although no attribute is involved. The message is clear. Spec D7 chose the existing code on purpose.
3. Low. A list field typed by a generating alias says `remove @onCreate(...)`, but the `@onCreate` is on the alias, not the field, and the message does not name the alias. The Mongo optional-field message does name it ("its type alias "Stamp" generates a value").
4. Low. `.onUpdate()` after `type.temporal.UpdatedAt()` says "do not combine .onUpdate() with a field preset that sets it". Here it was a contributed alias, not a preset. The `.default()` message already mentions alias constants; the phase message does not.
5. Low. The `String` and `JsDate` variants of `temporal.CreatedAt` and `temporal.UpdatedAt` have the same documentation as the plain ones, so completion does not tell a user how they differ (the TypeScript value they give).
6. Low, cosmetic. The upgrade script writes the new hash into `migrations/app/refs/db.json` before the database is signed, so `db sign` then prints `Advanced ref "db" → 0ce1b6cf3e… (was 0ce1b6cf3e…)`, naming one hash twice. Signing works.

Not from this slice: `main`'s `examples/prisma-8-demo/prisma/contract.ts` does not match its PSL (it has no `User.displayName`, among other gaps), so the TypeScript mode emits a different storage hash. Also, `pnpm build` of the `main` extract hung in the `retail-store` web build (20 GB of memory after 15 minutes); I stopped it, because the packages and the CLI had already built.
