## Observations

None of these breaks a stated acceptance criterion.

1. The upgrade script rewrites `@default(uuid())` inside a `//` line comment, and counts it. `extra.prisma` reported 6 rewrites for 5 real calls. The fragment says the script "changes nothing else". Harmless, but the count is off.
2. The upgrade script drops the spaces inside the call: `@default( uuid(7) )` became `@onCreate(uuid(7))`.
3. The script's message says `rewrote 1 @default calls`, with a plural for one call.
4. `contract print --format human > file` writes the PSL to standard output and also again to standard error after the success line (19 lines on standard error). I did not check whether `main` does the same, so this may not come from this slice.
5. A TypeScript builder refusal reaches the CLI only as `CONTRACT.SOURCE_LOAD_FAILED`, with the message under `why` and the generic hint `Ensure contract.source.load resolves to ok(Contract) or returns structured diagnostics.` The `--json` output has no `CONTRACT.DEFAULT_INVALID` code or `reason` (spec D10 says the builder throws `CONTRACT.DEFAULT_INVALID` with `reason: 'generator-not-applicable'`). A user sees a clear message but a hint that does not help.
6. Unrelated to this slice: in the `prisma7-adoption` copy, `db sign` advanced the ref `db` from `cee288aa57…` (committed in `migrations/app/refs/db.json`) to `9268d6eef6…`, the hash `main` emits too.
