# Deferred

- **Default functions still live on the adapters, and pack refs carry an empty default function registry.** The database default functions (`autoincrement`, `now`, `dbgenerated`) are still a `Map` on each adapter's `controlMutationDefaults.defaultFunctionRegistry` (`packages/3-targets/6-adapters/{postgres,sqlite}/src/core/control-mutation-defaults.ts`). Slice 1 put the generator descriptors on the component that defines each generator: the SQL family registers the identifier generators, and each target its `now` generators. They share `controlMutationDefaults` with the default functions, so five places give an empty `defaultFunctionRegistry: new Map()` only to satisfy `ControlMutationDefaults`: the Postgres, SQLite and Mongo target descriptor-metas (`packages/3-targets/3-targets/{postgres,sqlite}/src/core/descriptor-meta.ts`, `packages/3-mongo-target/1-mongo-target/src/core/descriptor-meta.ts`), the SQL family pack ref (`packages/2-sql/9-family/src/exports/pack.ts`) and `SqlFamilyDescriptor` (`packages/2-sql/9-family/src/core/control-descriptor.ts`). The planned change: when the default functions move off the adapters to the targets, as a declared contribution like the generator functions, split the generator descriptors into their own `ComponentMetadata` field next to `generatorFunctions`, and drop the empty registries. That is not part of this project.
