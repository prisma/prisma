# v8.0.0-rc.5

## Breaking changes

- **`aggregate()` now honours `take` / `skip` / `cursor` / `distinct` / `distinctOn` instead of silently ignoring them** — a root-level `db.orm.<Model>.take(10).aggregate(...)` used to reduce over every matching row regardless of any pagination clause in the chain; it now reduces over exactly the rows the chain describes, the same way `include('posts', (p) => p.take(10).count())` already did. If you wrote this pattern expecting the number back to answer "over everything", it now answers "over the paginated window" instead — read the [ORM collection chaining guide](https://github.com/prisma/prisma/blob/v8.0.0-rc.5/docs/reference/ORM%20Collection%20Chaining.md) to see which chain shape you want. ([#30067](https://github.com/prisma/prisma/pull/30067))

  Before:

  ```ts
  // Silently summed every post's views, ignoring take(10).
  const { total } = await db.orm.Post.orderBy((p) => p.views.desc()).take(10)
    .aggregate((agg) => ({ total: agg.sum('views') }));
  ```

  After:

  ```ts
  // Sums only the top 10 posts by views.
  const { total } = await db.orm.Post.orderBy((p) => p.views.desc()).take(10)
    .aggregate((agg) => ({ total: agg.sum('views') }));
  ```

- **Pagination around `groupBy()` now does what its position says, instead of being dropped** — `db.orm.<Model>.take(10).groupBy('x')` used to discard the `take(10)` entirely and group every row; it now scopes the rows that get grouped, matching Prisma's `aggregate()`. `GroupedCollection` also gained its own `take` / `skip` / `orderBy`, which page the groups themselves, matching Prisma's `groupBy()`. Chain position decides which one you get — see the [ORM collection chaining guide](https://github.com/prisma/prisma/blob/v8.0.0-rc.5/docs/reference/ORM%20Collection%20Chaining.md). Post-group `take` / `skip` require a prior post-group `orderBy`; without one, they are now a compile error rather than a query with no defined order. ([#30092](https://github.com/prisma/prisma/pull/30092))

  Before:

  ```ts
  // take(10) silently dropped — every user's posts were grouped, not just the top 10.
  const stats = await db.orm.Post.orderBy((p) => p.views.desc()).take(10).groupBy('userId')
    .aggregate((agg) => ({ total: agg.sum('views') }));
  ```

  After:

  ```ts
  // Groups only the top 10 posts by views, then sums each user's slice of them.
  const stats = await db.orm.Post.orderBy((p) => p.views.desc()).take(10).groupBy('userId')
    .aggregate((agg) => ({ total: agg.sum('views') }));

  // To page the groups themselves instead, put take() after groupBy():
  const page1 = await db.orm.Post.groupBy('userId').orderBy((g) => g.userId.asc()).take(10)
    .aggregate((agg) => ({ total: agg.sum('views') }));
  ```
